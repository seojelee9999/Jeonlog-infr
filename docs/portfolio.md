# 전록 — 전시 플랫폼의 개발환경·배포 및 운영 개선

| 항목 | 내용 |
| --- | --- |
| 프로젝트 | 전시 플랫폼 애플리케이션 전록(Jeonlog) |
| 기간 | 2025.11 ~ 2026.07 |
| 팀 | 8명 |
| 담당 | 개발환경 구축 및 배포, Grafana 대시보드 구성과 인프라 운영 개선 |
| 운영 | 약 6개월, 서비스 종료 시 회원 130명 |
| 주요 기술 | AWS, Terraform, Docker, Grafana, Prometheus, CloudWatch |

## 프로젝트 소개와 역할

8명이 참여한 전시 플랫폼 애플리케이션 프로젝트에서 개발환경 구축과 배포를 담당했습니다. 애플리케이션을 실행할 AWS 인프라와 배포 환경을 구성하고, 약 6개월간의 서비스 운영 과정에서 지표 확인 요구와 운영 비용 문제에 대응했습니다.

서비스 종료 시 회원 수는 130명이었습니다. 이 수치는 회원 수이며 MAU를 의미하지 않습니다. 운영 경험은 대규모 트래픽 대응 성과보다, 실제 이용 규모를 고려해 모니터링과 인프라 구성을 조정한 사례에 초점을 맞췄습니다.

## 인프라와 배포 구성

저장소에는 네트워크·ALB·ASG를 분리한 Terraform 모듈, ECR과 GitHub OIDC 배포 역할, SSM 이미지 파라미터 및 인스턴스 교체 설정이 있습니다. Prometheus의 EC2 자동 탐색, Grafana, CloudWatch 로그를 이용한 관측 구성도 포함합니다.

| 영역 | 구현 내용 | 근거 |
| --- | --- | --- |
| 인프라 코드화 | VPC·서브넷·보안그룹, ALB, ASG 모듈화 | [Terraform 모듈](../terraform/modules) |
| 배포 연계 | OIDC 역할, ECR push 권한, SSM 이미지 갱신 및 ASG 교체 권한 | [OIDC·배포 권한](../terraform/live/ecr/iam.tf) |
| 실행 환경 | 런타임 설정 및 이미지 조회, 컨테이너 실행 | [부팅 스크립트](../terraform/live/prod/scripts/user_data.sh) |
| 관측 환경 | EC2 자동 탐색 기반 Prometheus 수집, Grafana, CloudWatch 로그 | [모니터링 설정](../terraform/live/prod/scripts/grafana_setup.sh) |

이 코드는 운영 중 사용한 구성의 일부를 보존한 자료입니다. **운영 과정에서 ALB 제거와 모니터링 서버의 네트워크 배치를 변경했으며, 그 최종 상태가 현재 Terraform에 모두 반영되어 있지는 않습니다.** 코드와 운영 이력의 차이는 [운영 변경 기록](operations-history.md)에 정리했습니다.

## 문제 해결 1. 서비스 이용 지표를 확인할 대시보드 구성

**상황:** 운영 중 DAU·MAU 등의 서비스 이용 지표를 Grafana에서 확인할 필요가 있었습니다.

**수행:** 지표 확인 요구에 맞춰 Grafana 대시보드를 구성했습니다. 애플리케이션 실행 환경을 제공하는 역할에서 운영 데이터를 확인하는 환경까지 담당 범위를 넓혔습니다.

**결과:** 서비스 이용 지표를 대시보드에서 확인할 수 있는 환경을 마련했습니다. 다만 유의미한 MAU 성장 성과로 제시할 수 있는 수치는 없으므로, 사용자 성장 대신 지표 가시성 확보를 결과로 설명합니다.

저장소의 [기존 Grafana 화면](grafana-dashboard.png)은 CPU·메모리 등 인프라 지표 화면입니다. DAU·MAU 대시보드의 화면·쿼리는 추가 자료로 구분하며, 두 자료를 동일한 증빙으로 사용하지 않습니다.

## 문제 해결 2. DB와 모니터링 서버의 네트워크 배치 조정

**상황:** DB와 Grafana가 서로 다른 AWS 리전에 배치되어 있었고, 운영 중 리전 간 통신에 따른 비용 부담이 발생했습니다.

**수행:** Grafana 인스턴스를 DB가 위치한 리전의 같은 네트워크 대역으로 재배치하고, 두 자원을 비공개 접근 환경으로 구성했습니다. 관리자 접속에는 Bastion을 사용했습니다. Bastion을 Grafana의 지표 조회용 중계 서버로 사용한 것으로 설명하지 않습니다.

**결과:** 모니터링과 DB의 네트워크 배치 및 접근 경로를 정리했습니다. 인프라가 동작하는지뿐 아니라, 서비스 구성 요소의 위치와 통신 경로를 비용 검토 대상으로 다룬 경험입니다.

변경 전후 리전 이름과 세부 VPC·서브넷 배치는 현재 자료에 없습니다. 비용 전후 금액이 없어 절감액이나 절감률은 기재하지 않았습니다.

## 문제 해결 3. 서비스 규모에 맞춰 ALB 제거

**상황:** 운영 중 사용자 규모에 비해 인프라 비용이 많이 발생했습니다.

**수행:** 운영 규모를 기준으로 구성을 다시 검토하고 ALB를 제거했습니다.

**결과:** 기존 아키텍처를 계속 유지하기보다 실제 서비스 규모에 맞춰 운영 구성을 단순화했습니다. ALB 제거 후의 외부 요청 진입점, TLS 처리 방식, 가용성 영향과 실제 비용 변화는 추가 확인 항목입니다.

이 사례는 무조건 많은 구성 요소를 도입하는 것보다, 운영 요구와 비용을 함께 검토해 구성 유지 여부를 판단한 경험으로 설명할 수 있습니다.

## 운영 경험에서 강조할 역량

- **개발·배포 지원:** 8명 팀의 개발환경과 배포를 담당한 경험
- **관측 환경 구성:** 시스템 지표에 더해 DAU·MAU 등 서비스 이용 지표를 확인하는 대시보드 구성
- **비용을 고려한 운영:** DB·Grafana의 리전 배치와 ALB 유지 여부를 실제 운영 규모에 맞춰 검토
- **코드와 운영 이력 관리:** Terraform에 보존된 구성과 이후 변경된 운영 상태를 구분해 설명

## 증빙과 검증 범위

프로젝트 기간·역할·운영 기간·회원 수·운영 변경 사례는 프로젝트 수행자의 설명을 반영했습니다. 코드와 기존 인프라 대시보드 화면은 저장소에서 확인할 수 있으며, Terraform 구성 검사는 [검증 기록](verification.md)에 있습니다.

추가로 확보하면 좋은 자료는 DAU·MAU 대시보드와 집계 기준, 네트워크 변경 전후 구성, ALB 제거 후 요청 경로, 비용 명세입니다. 포트폴리오 정리 중 추가한 검증 CI와 코드 수정은 서비스 운영 당시의 성과와 구분합니다.

## 이력서용 요약

> 8명 규모 전시 플랫폼 프로젝트에서 개발환경 구축과 배포를 담당하고, 약 6개월간 서비스 운영에 참여했습니다. Grafana 기반 이용 지표 대시보드를 구성하고, 리전 간 통신 비용 문제에 대응해 Grafana를 DB와 같은 리전으로 재배치했습니다. 서비스 규모에 맞춰 ALB를 제거하는 등 운영 구성을 조정했으며, 서비스 종료 시 회원 수는 130명이었습니다.
